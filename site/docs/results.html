Test results

How well PhishGuard catches phishing, how fast it is, and how it holds up when attacked. Every number links to the raw evidence in the repository.

Catching phishing

Live phishing links from OpenPhish and phishunt.io, and real websites, were opened in the sandbox on 6 November 2026. The held-out batch was collected after the rules were written and scored once.

Held-out batch: 71 phishing pages, 61 real sitesPrevious versionPhishGuard now, without the lists
Phishing called Danger6%45%
Phishing warned (Danger or Caution)45%87%
Real sites wrongly warned10%0–5%
  • Why "without the lists"? That is the case that matters: a brand-new phishing site nobody has reported yet. With the lists every test link was caught, but only because the links came from those same lists.
  • Some phishing links showed the sandbox a decoy, such as a real Google page or a "403" error. Only the lists and the address rules can catch those; they are reported separately.
  • The samples are small (60 to 110 pages per group), so each figure is uncertain by about ±10 points.

Attacking PhishGuard itself

A tool that opens dangerous links must not become the way in. A security self-test starts a real engine, real fake attack sites, the real sandbox and a real Chrome window, and throws 63 attacks at it: network exposure, DNS rebinding, cross-site requests, authentication, SQL injection, path traversal, unsafe links, parser confusion, server-side request forgery, script injection, sandbox escapes, prompt injection, the link launcher and password guessing. All 63 are stopped.

One real problem was found while building that test and fixed: a backslash trick that made a link look like a trusted site to the app but open a different site in Chrome.
